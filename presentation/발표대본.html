창의성 강조 포인트 (40점)

  • 문제를 '창조'했다 — 구매 기록만 있는 데이터에서 negative sampling으로 Buy/Not 분류를 정의(최강 차별점).
  • 분석 → 제품화 — 같은 모델을 대시보드·플레이그라운드·REST API 세 표면으로 제공.
  • 데이터가 말하는 자동 인사이트 — 성장률·집중도·핵심고객을 코드가 문장으로 생성.
  • 신뢰의 디테일 — 카테고리별 이상치 제거, 시계열 backtest, 미지 입력 차단.
  • 로컬을 넘어 실제 배포 — Docker로 Hugging Face Spaces 라이브 배포(빌드 시 데이터·모델 자동 생성). 제출물이 아니라 상시 접속 가능한 제품.
  • 예측 로그 파이프라인 — 모든 예측을 Supabase(클라우드 DB)에 기록, 미설정 시 로컬 SQLite 폴백.

예상 질문 & 답변

  • 자전거 87% 편중? → 그래서 매출은 자전거, 고객관리는 Champions에 집중하라는 결론.
  • 구매예측 정확도가 너무 높다(과적합)? → 과거 활동 피처가 강한 신호. train/test 분리 + ROC-AUC로 평가, 신규 고객엔 실제로 낮은 확률(0.1%).
  • 이상치를 왜 카테고리별로? → 자전거($2천~)와 액세서리($5~)를 한 잣대로 자르면 정상 자전거가 이상치가 됨.
  • 시계열 정확도? → 마지막 6개월 숨기고 맞춘 backtest MAPE 19%.
  • 모델은? → 과제 요구대로 RandomForest 분류·회귀, 시계열만 Holt-Winters.
  • 실제 배포했나? → 네, Docker로 Hugging Face Spaces 배포(공개 URL). 빌드 시 데이터·모델 자동 생성, 예측은 Supabase 기록.
